# A dispatched agent never escalates — a gate's capability is declared in config, provided by setup, and withheld when absent

A consumer's first wave on 2.3.0 (issue #709, 2026-09-04) took 5h46 of wallclock, of which about five hours were one permission prompt: the Worker ran the build gates its brief demands, they failed inside the sandbox, it retried with the sandbox off, and the harness asked — in the Coordinator window, shortly after four in the morning, with nobody there. The tracked allowlist can permit a command; it cannot permit *disabling the sandbox*, so no allowlist entry could ever have answered. Grilled 2026-09-04 against ADR-0009/0030/0034/0041/0047/0048 and the shipped Worker and Reviewer briefs. Four findings shaped the answer. **(1)** The case had already been decided once, narrowly, and never generalised: `wave-setup`'s `docker` rule keeps an un-sandboxed command out of the tracked settings (a host-escape for every future agent of the repo) and briefs the Worker for graceful degradation with a precise deferral disclosure. **(2)** The Worker brief already names the danger — *"a permission dialog mid-AFK-dispatch has nobody to answer it and stalls your row"* — and two clauses later forbids the only click-free way out — *"never drop a gate because its literal form was refused"*. **(3)** The Reviewer's deferred valve already covers *"an outcome unreachable from the review environment — merge-gated, prod-gated, human-gated"*: the mechanism exists; only the trigger has no name. **(4)** The issue offers two remedies as alternatives — setup scaffolds the sandbox exception, or the brief lets the Worker defer the gate — and omits a third that was live on the reporting machine: the operator's *global* sandbox already widened the Xcode write paths, which is narrower than excluding a command and reaches nothing but that one machine.

## Decision

1. **Two levels, not two options.** The brief clause is a safety property; setup coverage is the optimisation above it. Setup can never enumerate every gate a consumer will cut tomorrow, so the floor lives in the brief and holds whatever the setup's quality: **a dispatched agent never escalates its own permissions** — unconditionally, attended or not. Attendance is not a property a run can carry: the reporting operator was present at dispatch (03:45) and absent when the prompt came. The rule binds every dispatched role — Worker, Reviewer, Scribe — and the Reviewer runs under **at most** the Worker's rights, never more: it executes the code the Worker wrote, so anything wider there is an escalation channel for whatever reached the diff through an issue body, and its re-run verifies the Worker's claim only under the same conditions — a `pass` where the Worker reported `deferred` would be a second, different run, not a verification. Breadth of *commands* is the Reviewer's already (the probe licence, the sibling merge-tree, ADR-0030's documented-form comparison); breadth of *rights* is not. The Coordinator is the Operator's own session and is not bound by it; there, the Operator clicks.
2. **A gate's need is declared in config as a requirement class, never as a harness knob.** `VerifyCommand` gains an optional `needs` — a closed set of three, each naming one sandbox dimension: `writes: [<paths>]` (outside the worktree), `network: [<hosts>]`, `host: true` (a daemon socket, a simulator, a device — the class that cannot be narrowed). The engine learns the *need*; the skill tier translates it into the harness binding. That keeps the engine harness-agnostic (ADR-0009) and gives the Reviewer — which independently re-runs the same commands and meets the identical wall — the same data the Worker has. An optional field that existing configs never carry: a minor.
3. **Setup provides it, and measures that it did.** `wave-setup` translates `writes`/`network` into the **tracked** `.claude/settings.json` `sandbox` block (`filesystem.allowWrite` / `network.allowedDomains`): narrow, path-exact, reviewable in the PR that lands it, and — the deciding fact — the only home that reaches a dispatched worktree and a headless runner (ADR-0048), neither of which carries operator settings. `host` is declared tracked but provided **operator-local only**: the `docker` rule, now stated as the rule for its whole class — a tracked command exclusion is a host-escape granted to every future agent of the repo. Setup then runs each `needs`-bearing command once *inside* the sandbox. The "proven by execution, not inspection" standard that already binds a verify command's *form* extends to its *capability*, so a declaration the harness does not honour fails at setup, not five hours into a wave.
4. **A withheld gate defers the acceptance criteria it would have backed — the row continues.** The Worker reports the command as not run, and why, through the channels it already has (`tests` / `lint`, `judgmentCalls`); no return-schema change, so the byte-identical drift guards and the plugin/engine lockstep stay out of play. The Reviewer's deferred valve gains its fourth trigger, `capability-gated`, beside merge-, prod- and human-gated: the affected ACs land `deferred` or `partial`, are mirrored into `reviewerFocusItems`, captured as a Disclosure at routing and dispositioned before archive (ADR-0027); a deferred core path pulls in the documented-form comparison exactly as it does today (ADR-0030). The human act moves from a blocking click to a non-blocking Disposition. A `host`-class gate deferring on a runner is the *expected* line, not a defect — the tracked declaration is what makes it honest.
5. **The brief carries the requirement as data, and the system learns one round late.** Both briefs render the row's verify commands with their declared needs, the way ADR-0041's scope grants render. A declared-and-provided gate is an ordinary gate. An undeclared need the agent meets is not a licence to escalate but a deferral whose disclosure names the command; the operator turns it into a declaration, and the next wave carries it. The same-round boundary of ADR-0041, by design.
6. **Enforcement tier: a brief clause, not a convention.** One consumer, one occurrence, one file — the shipped driver's two briefs — earns the prose tier (ADR-0034), with this record as its why. A Convention 17 would add to a corpus the loading model already pays too much for (#714) before a second occurrence has argued for it.

## Considered Options

- **The issue's two remedies as alternatives** (rejected) — they sit at different levels; choosing one forfeits either the floor or the coverage.
- **"Never disable the sandbox" as the rule** (rejected) — names one harness's knob; the `docker` case and the refused `.claude/settings.json` write are the same class and would not be caught.
- **An attendance flag in the brief** (rejected) — falsified by the case itself: present at dispatch, absent at the prompt.
- **A wider-privileged Reviewer, so it can test more broadly** (rejected) — the Reviewer runs the Worker's code, so wider rights there are the escalation channel; and a Reviewer `pass` on a gate the Worker could not run compares two environments, not two runs. Breadth belongs to its commands, which it has.
- **Probe before running** (rejected) — the prompt *is* the probe; there is no way to test a permission without requesting it.
- **A `capability-required` STOP reason with a `grant` continuation** (rejected) — a full Worker round per first encounter, and a semver-visible change to the closed Answer contract (ADR-0047) for a case the deferred valve already absorbs.
- **`changes-requested` on a withheld gate** (rejected) — punishes a finished, correct row for a setup gap, and buys a round that can change nothing.
- **Only the pre-dispatch coverage check learns the case** (rejected) — `verify-profile-coverage` runs before dispatch and cannot know a runtime refusal; #711 is the static half of this signal, #709 the dynamic half, one channel.
- **A boolean `unsandboxed` or a free-text reason** (rejected) — the first puts the knob in the engine and forces the broad translation always; the second translates to nothing.
- **Everything operator-local** (rejected) — dead on a runner and for a second operator; the declaration would have no provider.
- **Everything tracked, `host` included** (rejected) — the `docker` rule; the first Linear consumer wave's security review flagged exactly this.
- **Tracked, but documentation only** (rejected) — without the setup-time measurement the declaration-vs-provision mismatch surfaces mid-wave again.

## Consequences

- **Engine:** `VerifyCommand.needs` (optional; closed set validated at `config validate`); `compose-driver` renders each verify command's needs beside it in both briefs; `verify-profile-coverage` (#711) and this decision share one signal — *this approve is not verify-backed* — as static and dynamic halves; a scaffold guard for the tracked `sandbox` block's parity with declared `writes`/`network` is the natural sibling of the allowlist guard.
- **Skills:** `wave-setup`'s verify interview gains the needs question and the sandboxed measurement, and its `docker` note becomes the `host`-class rule; the Worker and Reviewer briefs gain the no-escalation clause and retire the retry-with-the-sandbox-off path by name; the Reviewer contract names `capability-gated` as the valve's fourth trigger.
- **Docs:** CONTEXT gains **Capability requirement** and the "deferred" ambiguity ruling; ADR-0041 stands as the structural precedent (a grant travels in the brief); ADR-0048's pulse meets this seam first and is unblocked by it.
- **Semver:** minor. The Ask/Answer comment contract (ADR-0047) is untouched.
- **Open, deliberately:** whether the harness merges a project-tracked `sandbox` block with the user's global one is an assumption the implementing row measures first (Convention 11: prove the check can fail). If it does not, decision 3's tracked home needs a different carrier and this record is amended, not silently worked around.
- This record lands Coordinator-direct (ADR-0033: it closes no issue). The implementation goes through reviewed wave rows — #709 for the brief and setup halves, #711 as its static sibling.
