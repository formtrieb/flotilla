# A goal binds a native container and derives its frontier

flotilla's pipeline had no destination concept: waves optimized throughput while "1.0.0" was defined nowhere, until a hand-driven cut (a GitHub Milestone minted via raw `gh api`, membership `{#372, #376}`, human decision throughout) proved the shape a goal needs — and proved it needed *zero* engine surface for a maintainer working one tracker by hand. The 2026-07-31 evaluation of Matt Pocock's Wayfinder skill yielded two landed issues (#381 native-dependency read-union, #382 doc borrows) and four field issues as a requirements list by counter-example: 703 (the planning/execution boundary was prose — seven PRs walked through the open gate), 683 (an agent wrote itself a release authorization into the map's free-prose notes and executed against a live server), 661 (the planning→execution exit seam never became typed), 599 (remote writes against an unconsented tracker). A grill on 2026-08-15 settled the design: a **Goal** — a named finish line whose members are issues in a config-bound native container — and its **Frontier**, the derived open remainder. The colliding conventions that forbid any built-in container assumption are live and named: one Linear consumer runs Initiative=Epic / Project=User Story (motivated by Linear's timeline and health views living at project/initiative level, not on issues), while ADR-0017 once sketched "Wave ≈ Linear Project".

## Decision

1. **The `goal` station creates bare frontier tickets — existence first.** At a goal's cut, you know *that* a workstream must exist before anyone can say *what* it is. The station files such members as bare issues (H1 + prose + provenance line — no Header-Block, no eligibility stamp), generalizing the Disposition-`filed` discipline: existence is recorded, wave-readiness is not implied. Sharpening bare→ready stays where it lives — triage's answerability test and `to-issues` decorate-mode; the station never stamps `ready-for-agent`. Because such tickets can depend on each other before either is definable, the BARE create form gains an optional `blockedBy` arm realized natively per adapter (GitHub native issue dependency, Linear relation, MarkdownFs degrading honestly — the `closed-unknown` precedent: report what the store cannot represent, never fake it). The #381 read-union then makes those edges visible to conflict reasoning with no header required.
2. **A Goal is an issue-set boundary, orthogonal to PRDs — never a hierarchy over documents.** Completion must be a query, and only issues have queryable native state; a PRD is *consumed* (derived from `Parent` backlinks), never "done", and making it a member would demand exactly the written completion state ADR-0011/0013 refused. A PRD belongs to a Goal only derivedly — through member slices. The hand-driven 1.0.0 cut already lived this shape: an issue set across origins, the open PRD explicitly outside. The frontier is deliberately editable: a bare member that outgrows its placeholder becomes a PRD whose slices *join by curation* while the placeholder closes — a human act at slicing time, never an automatism.
3. **The Goal earns an `IssueStore` facet** — reversing the 2026-07-31 note "milestones are a product artifact, deliberately outside the seam", which was true for a maintainer's hand-driven cut on one tracker and flips for a shipped skill: Linear writes must flow through the Credential-Resolver (Convention 8, ADR-0029 — a skill cannot raw-call Linear at all), the raw-`gh`-in-skill defect class was already paid for once and structurally retired by the Triage facet (ADR-0015), and MarkdownFs has no native container — the facet *is* its realization. The verb set is minimal and read-heavy: `createGoal · readGoal · listGoals · assignToGoal` plus the frontier query; one conformance suite across all three stores. Deliberately absent: dispatch verbs (none, ever — see 6) and `closeGoal` (see 5).
4. **The container role is a setup-time config binding, fail-loud when absent** (`engine.cli` discipline, ADR-0032; "configured means authoritative", ADR-0029). GitHub may default to Milestone — the only native container with direct issue membership, a default no consumer convention can collide with. Linear gets **no default**: the binding is explicit, and v1 ships only the **Project** realization. The **Initiative** realization is a named follow-up, not a silent cap: initiatives hold projects, not issues, so its membership is transitive and may not be `assignToGoal`-shaped — while its motivation is real and recorded (timeline and health views; the consumer running Initiative=Epic cannot bind Goals until it lands). Goal size is thereby a consumer decision expressed in the binding, never flotilla's.
5. **The Frontier is derived, never written, and the station never declares.** Each member reads as `done` (natively closed — the coarse bookend, ADR-0003/0005; merge-evidence stays wave-close's per-issue concern) or one of four open states: `in-motion` (claimed), `actionable` (eligible, unblocked, unclaimed), `blocked` (unresolved dependency via the read-union), `unready` (bare — needs sharpening). Completion is literally *the frontier is empty* — and even then the station only reports it; closing the container is the Operator's act in the tracker, **not a facet verb**. There is no durable release marker an agent could write, and no map document for one to accumulate in (field issue 683) — state lives in the container and the query. The station owes accounting, never the declaration (ADR-0042's sentence, one station over).
6. **Sight, never permission.** Goal membership informs planning and authorizes nothing: `wave-plan` may read the facet for a goal panel/filter, execution skills (`wave-create` onward) never consume it, and the planning→execution seam stays the existing typed one — Eligibility OR-set + DoR (field issues 703/661: the boundary is structural, a schema boundary rather than brief prose, per the ADR-0034 ladder). The station's writing passes (cut, curation) each preview and confirm — per-pass human yes, no pass rides on an earlier pass's approval; the status pass is read-only and free.

## Considered Options

- **Zero engine surface — skill prose over `gh api`** (rejected) — the precedent that suggested it dissolves on inspection: the hand cut had one tracker, ambient `gh` auth, and a maintainer deciding; a shipped skill has three stores, a credential seam a skill may not cross (Convention 8), and the already-retired raw-CLI defect class (ADR-0015).
- **Goal as a PRD variant — a checklist document** (rejected) — completion by checklist is completion by prose, Wayfinder's measured failure mode (703); and it would re-open the written-completion-state door ADR-0011 closed.
- **Goal → PRD → slices hierarchy** (rejected) — requires "PRD done", which deliberately does not exist.
- **Membership as an eligibility input — goal issues auto-qualify or rank first** (rejected) — a planning artifact granting execution rights is precisely the 703 hole; the OR-set stays the only gate.
- **"milestone" as the canonical name** (rejected) — names one native realization of a config-authoritative role, and collides head-on with Linear's project-scoped Milestones, which the binding *excludes*.
- **Linear Initiative realization in v1** (deferred, not rejected) — transitive membership is a contract-shape question worth its own design, and no bound consumer exists until it lands; filed with its motivation attached rather than built speculatively.
- **A durable map/notes artifact beside the container** (rejected) — free prose beside a goal is where Wayfinder's agent minted its own release authorization (683); flotilla's goal state is container + query, nothing else.

## Consequences

- CONTEXT.md gains **Goal** and **Frontier** (Planning) and a Relationships line; the internal working title "Map-Station" retires — the station is named for what it manages: `goal`.
- Four follow-up issues file bare, each with this ADR as provenance: the Goal facet (engine), the `goal` skill (station: cut/curation/status passes), the BARE-create `blockedBy` arm, and the Linear Initiative realization (carrying the timeline/health motivation and a note that a future Linear health write-mirror — publishing the frontier report as a native Project Update — belongs behind the facet).
- The skill pipeline's front half gains a fourth station when the skill lands: `goal`, `triage`, `to-prd`, `to-issues`.
- This ADR lands Coordinator-direct (ADR-0033: it closes no issue).
