# The sweep owes accounting, never removal

The worktree sweep resolves a set of containment roots and enumerates its populations only inside them. Two residue classes escape it, both measured live in wave `2026-08-14-setup-credential-table`, and both end in the same operator experience — a manual, sandbox-off removal — with the report claiming less than the sweep knew.

**Residue the sweep sees but cannot remove (#560).** A plainly-clean worktree whose physical delete is blocked by harness-denied content reads TRANSIENT on its first close and EXHAUSTED only on the second. The between-runs measurement (top-level listing byte-identical, only tracked-file deletions under the denied paths) together with a code reading shows why this is structural, not a fluke: the `deniedResidue` predicate (issue #542) asks *"is every physical survivor harness-denied?"*, but the aborted-early delete has not yet exhausted its permissions when the question is asked — on a full tree at first attempt the survivor set always contains ordinary deletable content, so the predicate can fire only on a tree a *previous* run already stripped. The two-run flip is the only trajectory on which this signal can ever fire. Its spec passed because the fixtures model the end state, never the first-attempt state. The verdict the walk computes is then discarded after the exhaustion decision; no report field ever names what survived.

**Residue the sweep never sees (#557).** A Reviewer probe checkout in a per-session scratchpad is registered and counted, but inside no containment root — visible to `worktreeCount`, absent from every list, and `cleanup.extraRoots` (static strings) structurally cannot name a path that changes every session. The prose that denies the Reviewer `git worktree remove` justifies the refusal with "a leftover probe is exactly what the detached-scratchpad sweep reaps" — false for exactly this population. Today's only remedy is a documented hand-diff of the count against the union of every report array.

## Decision

1. **The sweep owes accounting, never removal.** For residue it cannot remove or cannot see, the sweep's duty is to name it — precisely, machine-readably, on the first run that observes it. Removal authority stays where it is today: with the Operator. No more-forceful engine delete, no register-following sweep, no reliance on a probe's self-cleanup as the guarantee.
2. **Survivor disclosure now; the delete-path rebuild waits for a live read.** The incomplete-removal report entry additively gains its evidence: the surviving paths (bounded, with a total) and the already-computed exclusively-denied verdict that is currently dropped. Classification semantics stay byte-identical. The rebuild that would let run 1 say EXHAUSTED — exhaust permissions in one best-effort pass, *then* judge survivors — is deliberately deferred: the session record currently contradicts itself about the live case (whether the 62 measured paths were the deleted set or the refused set), and the two prior fixes in this class (#528, #542) were each falsified on their first live read. The new field is the instrument that settles the question; the rebuild decision reopens with that reading in hand.
3. **`unaccounted` is advisory, never a failure.** A registered worktree that is neither the primary checkout nor in any population is reported in an additive `unaccounted` field plus a notice line (the `worktreeCount`-threshold pattern). It never joins the failure exit: the set has a legitimate inhabitant — a human's long-lived second worktree — and a red close would push exactly the wrong fix, putting a human workspace under containment to silence the alarm. Per ADR-0035: additive field yes, new failure condition on a shipped exit contract no.
4. **The refusal keeps its design; its justification is corrected.** The Reviewer still gets no `worktree remove`. The guarantee behind the refusal changes from *"the sweep reaps it"* to *"the sweep names it"* — the setup-mechanics rationale and the phase-3 hand-diff teaching are rewritten in the same diff that ships `unaccounted`, not before (docs walk with the code).
5. **The probe's location is a measurement, not a design guess.** The repo's own records contradict each other on whether an in-repo probe checkout comes up degraded-but-usable or aborts under the harness deny list. One probe under the worktrees root at the next live review answers it (does it come up · what does `git worktree add` exit with · is it usable without the denied content). Prescribing a canonical probe location is deferred to that outcome; with `unaccounted` shipped, an out-of-root probe is meanwhile never invisible — only unremoved.

## Considered Options

- **The sweep follows the git register instead of containment roots** (rejected) — inverts the safety model: today every "may I touch this?" is inherited from containment; a register-driven sweep would re-derive each refusal (primary checkout, human worktrees, foreign tools' checkouts) individually, and each miss is a deleted workspace.
- **Probe self-cleanup as the guarantee** (rejected as guarantee, welcome as hygiene) — fails precisely when residue is likeliest: a review that errors out or is killed never reaches its own cleanup step.
- **`unaccounted` as a failure exit** (rejected) — see Decision 3; the false-positive inhabitant is legitimate and permanent.
- **Exhaust-then-classify now** (deferred, not rejected) — touches the delete core (git-last ordering, bounded retry, the scoped force fallback) on evidence the record itself still contradicts; instrument first.

## Consequences

- #560's implementation scope becomes the survivor evidence on the report entry (additive, Minor per ADR-0035); its structural finding — the predicate can only fire on a stripped tree — is recorded on the ticket, and the rebuild decision reopens after the next live close is read with the field present.
- #557's implementation scope becomes the count-vs-lists reconciliation (`unaccounted` field + notice) plus the two prose corrections riding the same diff.
- The next wave close is the first live read of the survivor field and settles the deleted-vs-refused ambiguity in the #560 record.
- The probe-location measurement rides the next live review; its outcome decides whether a canonical location becomes its own small ticket.
- CONTEXT.md gains the cleanup vocabulary (Sweep, Containment root, Transient/Exhausted, Manual recovery, Survivor set, Unaccounted) and corrects the Worker entry's stale `/tmp` claim.
- This ADR lands Coordinator-direct (ADR-0033: it closes no issue); both implementations go through reviewed wave rows on #557 and #560.

## Amendment 2026-09-08 — The delete exhausts before it judges; a terminal wave's residue is not live; the sandbox-off step belongs to whoever runs unsandboxed

*The reading Decision 2 deferred on arrived (issue #748 item 2, close of wave `2026-09-06-contracts-and-briefs`, 2026-09-07): six clean Worker worktrees, each `erroredStillListed` with `survivors.total` 1724 exact, `exclusivelyDenied: false`, the twenty-path sample carrying `CHANGELOG.md`, `LICENSE` and the issue templates beside the harness-denied `.claude/agents` and `.vscode`. A consumer had read the same shape on 2.3.0 three days earlier (433 survivors, issue #621). Grilled 2026-09-08 against this record, ADR-0009/0035/0036/0048/0049, the phase-3 close reference, the wave-start driver reference and `worktree-cleanup.ts`.*

**What the reading settles.** The predicate was never wrong; it was asked of the wrong tree. Phase 1 of the physical delete is a loop over the worktree's top-level entries, each removed recursively, and the first refusal ends the loop (`physicallyDeleteGitLast`). In every measured run the loop reached `.claude` — which holds the denied `agents/` — before most of the tree, so the delete stopped after a handful of files with the whole tree standing: 1724 survivors, two of them denied. Under that order `exclusivelyDenied` is structurally unreachable, and run 2's EXHAUSTED is reached by the oldest signal, not by the residue probe: run 1's few deletions under `.claude/` are all harness-listed, so run 2 classifies the tree `dirtyAllJunk`, takes the force route, fails, and reads EXHAUSTED by `forceEligible` — the probe has no live occurrence on record. Three fixes (#528, #542, #560) read evidence that comes into existence only *as a result of* the first failure; #621's hypothesis is confirmed. The phase-3 line that calls a first-attempt `exclusivelyDenied: false` "expected, not a defect" was true of the shipped delete order and is a defect by this decision.

### Decision

6. **The delete exhausts its permissions before it judges.** Phase 1 becomes a best-effort pass: every entry is attempted, refusals are collected, the walk continues; `.git` stays last and is never reached when anything was refused. What stands afterwards *is* the Survivor set — the refused set and nothing else — and run 1 reads EXHAUSTED with Manual recovery on the same input run 2 needed until now. The three EXHAUSTED signals keep their definitions; the third can now fire on the shape it was built for. The "more doomed work before reporting" objection does not survive the measurement: the deletable content is deleted either way, by the engine or seconds later by the Operator's hand step — the pass only moves *who* deletes it and buys the reading and the evidence. The transient case improves with it: a Finder-dropped `.DS_Store` is then the only survivor, and the bounded retry's purge clears it.
7. **A physically exhausted tree is the sweep's own on every later run.** After decision 6 the worktree is dirty in git's eyes — ordinary tracked files deleted — and `planCleanup`'s `dirty && !dirtyAllJunk` rule would skip it as `dirty` with 1,700 blocking paths, on a tree the engine itself gutted; a pulse's re-run or the Operator's second call would lose the reading. The plan step therefore gains a second route to disposability: a dirty worktree whose *physical* survivors are exclusively harness-denied (the same walk, asked at plan time) is disposable, force-eligible, and re-reads EXHAUSTED with the same commands — idempotent, no state outside the tree. The guard against real work holds: a modified file, or an untracked file outside the junk allowlist, falsifies the walk at once. Rejected: a marker file written by run 1 (state that lies the moment someone writes into the directory); accepting the `dirty` skip.
8. **The sandbox-off step belongs to whoever runs outside the sandbox — never to an agent.** After decision 6 the residue is a handful of harness-denied units plus `.git`, and the commands are on the report. An agent does not toggle the sandbox (ADR-0049), and no declared need can provide the path: the denies on `.claude/agents` and its kin are the harness's own list, which no repository configuration overrides — by design, since an agent that could delete its own config could rewrite it. Interactively the Operator runs the two commands. Headless, the runner script *around* `claude -p` is the only unsandboxed process there is; a post-pulse step there that re-invokes the ordinary sweep removes the residue with no new force and no agent escalating — a runner script is not an agent. A Pulse (ADR-0048) therefore *reports* Manual recovery as **hygiene owed** in its exit report — advisory: no Ask, no failure exit, on Decision 3's reasoning that a red close pushes the wrong fix — and the existing worktree-count threshold notice is the brake on accumulation. On an ephemeral CI runner the class is moot. The runner-scaffold line itself belongs to the runner-shape decision, not here.
9. **The branch sweep names what it defers.** `computeOrphanBranchSweepPlan` drops a branch checked out in any registered worktree silently — neither deleted nor skipped — and git refuses to delete a checked-out branch anyway, so while an exhausted worktree stands its branches cannot fall: sweep → recovery → sweep is structural, not a defect of run 1 (issue #748 item 1). The defect is the silence. The result gains an additive key for **deferred** branches — deferred, not skipped: they *will* be deleted once the worktree is gone — naming branch, worktree and reason; and Manual recovery gains a third line: re-run the same sweep call after the two commands, because branch hygiene fires only on "worktree gone". How that line spells the invocation is the row's — the engine does not know its own CLI binding. Rejected: deregistering after exhaustion so the branch sweep can run in the same pass (breaks FOR-34 — git is never told to forget a worktree we could not delete — and turns a registered, recoverable remainder into an orphan directory whose recovery is the documented fallback `rm -rf`); adding `git branch -D` to the Operator's commands (a human re-deriving merge evidence the sweep already holds).
10. **A terminal wave's residue is not live.** The review-ref sweep (issue #732) spares any ref whose row is in the `--wave` spine, so at a wave's own close every ref it produced is `live-row` and the wave cannot sweep itself; its refs fall one close later (issue #748 item 3). The lag is not only clutter: the Reviewer's fetch into `refs/review/<id>` is not forced, so a stale ref for an id that returns in a later wave — a parked row re-planned — against a rebased branch is a rejected fetch, and under row membership a parked row's ref survives *two* closes. The rule becomes the close's own gate: **a wave every row of which is terminal (`pr-created`, `approved`, `failed`, `abandoned`, `parked`) has no live residue** — no Worker or Reviewer can be running for it; a wave with any non-terminal row keeps every ref spared, as today. Wave-level, not per-row: a per-row rule would sweep a finished sibling's `refs/sib/<id>` from under a still-dispatched Worker's merge-tree prediction. The spine carries the states, the CLI derives the answer, no new flag; `live-row` keeps its meaning for a mid-wave standalone run.
11. **Composed drivers are a sweep population under the same rule.** The wave-start driver reference promises that "`worktree-cleanup` sweeps the file at close with the rest of `.flotilla/tmp/`"; the Scribe scratch sweep selects only top-level `report-*`/`verdict-*` payloads and reports the per-wave `<slug>/` directory as `not-a-scribe-payload` — correctly — and leaves it (issue #748 item 4). The promise is false today and becomes true: a `<slug>/` directory under the scratch root is its own population, reported under its own key, removable when its wave is terminal (the `--wave` spine at its own close) or its spine is already archived; skipped `live-wave` for a running sibling; skipped `unknown-wave` — accounting, never removal — when no spine matches. Rejected: deleting it in the archive phase (a deletion inside the claim-safe archive gate, ADR-0036, and a standalone sweep would still never see it); correcting the prose to "nobody sweeps it".

### Considered Options (the delete core)

- **Say honestly that a second run is required** (rejected) — run 1 reports "aborted at first refusal, inconclusive"; cheap, but every close becomes sweep → sweep → recovery → sweep, and the reading is still one run late.
- **Re-classify inside the same run after the failed attempt** (rejected) — run 2 pulled into run 1; it depends on run 1 having deleted *something* under `.claude/` first, which the delete order happens to do today and nothing guarantees. A hack on a side effect.
- **Exhaust, then judge** (chosen) — decision 6, with decision 7 as its necessary companion.

### Falsification — the measurement this amendment owes

The first close on a sandboxed harness after decisions 6–11 land is the live read, stated before it is taken (measure with controls). **Positive control:** each Worker worktree reads `erroredStillListed` on **run 1** with `manualRecovery` present, `survivors.exclusivelyDenied: true` and a single-digit `survivors.total`; the wave's own review refs and its composed-driver directory are removed on that same run; its branches appear deferred by name. After the two commands run outside the sandbox, **run 2** deletes those branches. **Negative controls:** a worktree with no harness-denied content still reads `removed`; the transient-race regression specs stay green; a worktree with a modified tracked file is still skipped `dirty`. A run 1 that reads TRANSIENT again, or a survivor set that still carries ordinary content, falsifies decision 6 and reopens this record — and the next release's notes say so rather than carrying an "unproven" line forward, which is what issue #621 asked of 1.5.0's.

### Consequences

- **Semver (ADR-0035):** Minor with a heads-up. Nothing is removed and no exit code moves; the deferred-branch list, the driver population and the third recovery line are additive keys — chosen over widening an existing `reason` vocabulary, which the record reads as major-class. Two behaviours change for the same input and are named in the release notes: run 1 now reads EXHAUSTED, and a terminal wave's own close now removes the refs and drivers it used to spare.
- **Rows:** two, serial, same file. Issue #621 carries decisions 6–7 and the falsification spec, and flips the phase-3 paragraph that calls a first-attempt `exclusivelyDenied: false` expected. Issue #748 carries decisions 9–11 and makes the wave-start promise true; its item 2 is satisfied by #621's row. Decision 8's hygiene-owed block is not a row: it lands with the slice that builds the Pulse (ADR-0048), and the runner-scaffold step with the runner-shape decision.
- **CONTEXT.md:** Survivor set is now post-exhaustion; Manual recovery names its owner; Sweep gains the two populations and the liveness rule; **Terminal wave** enters.
- Decisions 1–5 stand. Decision 2's "deliberately deferred" is resolved by decision 6; its instrument, the survivor field, stays — now reporting the refused set rather than an aborted tree.
- This amendment lands Coordinator-direct (ADR-0033: it closes no issue); both implementations go through reviewed wave rows on #621 and #748.
