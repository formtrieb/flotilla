# User-directed output holds the operator register — internal references translate at the audience boundary

flotilla's first fully-external consumer (installed form, `linear` store, Bitbucket code host) ran setup and a first wave on 2026-08-13. The operator's experience, plus the session's field reports (#492–#494), surfaced a defect no gate had ever measured: agents speak to consumers in the maintainer register. An audit quantified the cause — none of the 12 skills carries any rule for how to address the human; skill prose holds 369 ADR citations; the YAML `description` fields (the first thing a consumer ever sees) carry `DoR`, `HELD`, `WAL`, a bare `(ADR-0023)`; report steps prescribe finding ids (`KW-F4`) inside human-read output; several skills address the human as "the Coordinator"; engine messages cite ADRs the npm package does not ship; hook teaching-texts recite occurrence history. Convention 14 had already named the symptom ("internal diary to a plugin consumer who was never in the room") but governs only citation *placement inside skill prose* — the agent's own output, the surface the consumer actually reads, was ungoverned. Three audiences exist (the executing agent, the maintainer, the operator); the corpus served two.

## Decision

**User-directed output holds the operator register — a speech register defined as Convention 16, distinct from skill prose, applied at the audience boundary.** Skill prose keeps its load-bearing why and its provenance positions (Convention 14, unchanged); what changes is what crosses to the human.

- **The Operator is canonical** (CONTEXT.md): the person at the live session — a role, not an identity. "The Coordinator" is the session, never the person; the skills that used it as an address are wrong by glossary and get corrected at clause rollout.
- **Five clauses.** (1) *Translation*: internal references — ADR numbers, convention numbers, finding ids, wave slugs, retro paths — never appear in operator-directed text; the agent states the one-line consequence instead. (2) *First-use introduction*: a domain term the operator should meet (Wave, Spine, Worker, Reviewer, HELD, arm, Disclosure …) gets a half-sentence introduction at first use per session, then flows freely. (3) *Address*: direct address ("du"/"you") is preferred; "Operator" is the prose role term, not the salutation. (4) *Operator block*: every skill run ends with what happened → where it lives → what you do next, each item place/shape/consequence — the wave-setup step-11 pattern, generalized to all 13 skills. (5) *Language*: operator-directed text follows the operator's language; artifacts (issues, PRs, ADRs, spine entries) stay English — the report-skill precedent, made explicit corpus-wide.
- **The form switch.** Installed form (every consumer): strict — no internal tokens in operator-directed text. Source form (flotilla itself, the only source-form repo): the compact reference pointer may follow the plain text — `…gemergt wird erst bei grünen Checks (ADR-0023)`. The switch binds to the existing static form binding (ADR-0032); no new signal. A power operator in a consumer repo who wants the pointers asks for them in-session — conversation, not configuration.
- **Where it lives.** A byte-identical short clause in every SKILL.md body; the long form plus the operator mini-glossary (~10 terms with their half-sentence introductions) as `wave-shared/reference/convention-16-operator-register.md`, reached via the ADR-0040 sibling-path read — which is how the front half, which never loads wave-shared, reaches it too.
- **Enforcement (ADR-0034).** Two guards land structural on day one, at drift-spec tier: a *descriptions guard* (no internal id patterns — `ADR-\d+`, `FOR-\d+`, finding ids, "Convention N" — plus a curated stop-list for the description surface) over every skill's and the Reviewer agent's frontmatter; a *clause drift guard* deep-equaling the short clause across all 13 bodies against one source constant. The runtime speech behavior itself stays prose — per doctrine the legitimate draft mode; a live register breach reaching a field report is the named promotion trigger.
- **Engine and hook messages.** One policy for both forms, fixed at authoring time: a user-visible message carries *what is wrong* and *what to do* and stands on its own; no bare internal tokens; where background genuinely helps, at most **one** URL pointer to the public ADR file ends the message. Occurrence history leaves the hook teaching-texts (it is provenance; its Convention-14 position is a source comment). Text changes are semver-neutral by the house's own no-message-matching doctrine (ADR-0029/0032).

## Considered Options

- **Strict everywhere, no switch** (rejected) — strips the source-form operator (the maintainer dogfooding) of the reference precision their own workflow runs on; the register would cost the one audience it was not written for.
- **Pointer-compromise everywhere** (rejected) — keeps the tokens in the consumer's view. The #492 credential message already *had* the action and still read as cryptic: the tokens plus insider vocabulary were the noise, not a missing instruction.
- **Full convention text in every skill** (rejected) — 13 drifting copies; the schemas-are-copies discipline with its drift guard exists precisely against this.
- **All 13 skills load wave-shared** (rejected) — couples the front half to schemas and routing mechanics it never uses, and inherits the by-name loading defect instead of routing around it (ADR-0040).
- **Hook-enforcing the register** (rejected) — a PreToolUse hook sees commands, not answer style; wrong layer, structurally.

## Consequences

- Rollout is three reviewed wave rows (ADR-0033): the long form + short clause + clause guard; the descriptions rewrite + descriptions guard; the engine/hook message pass (~8 known sites + 2 hooks). This ADR and the glossary land Coordinator-direct and close no issue.
- CONTEXT.md carries **Operator** and **Operator register**; **Coordinator** is sharpened ("the session, never the person"); it lands with this ADR.
- The report prescriptions inside wave-plan/wave-create that currently write finding ids into human-read output are corrected in the same rollout row that plants the clause.
- The YAML descriptions become consumer-legible — the skill listing is part of the consumer surface, and the descriptions guard keeps it that way.
