# A deferred core path makes the documented-form comparison required Reviewer evidence

A release workflow was reviewed and approved with three divergences from the registry vendor's documented example still in it — one flagged by the Worker as arguable, one (dependency caching in a release build, vendor-advised-against on supply-chain grounds) reported by nobody, surfaced only because the Coordinator happened to open the vendor's documentation for an unrelated question. Nothing malfunctioned: the Reviewer verified every acceptance criterion and every one held. The gap is a class, not an incident — the row's core path (the OIDC exchange with the registry) **cannot be executed before a real release exists**, so "does this match the form the vendor documents" was not one evidence source among several; it was the only one available, and no acceptance criterion asked for it, because ACs describe what a change should *do* and this is a question about what it should *look like*. Carried into the following wave as a hand-attached Reviewer hint, the check worked immediately — which proves the behavior and indicts the mechanism: a hint protects the row somebody already thought to protect. Issue #112 filed the contract change and deliberately held the trigger question open for an ADR. Since the filing, the ADR-0004 Amendment (2026-07-28) gave the Reviewer contract the outcome-evidence bar, the probe license, and the **deferred valve** — the vocabulary this decision anchors on. Settled in a grill session 2026-07-29.

## Decision

- **The trigger is the deferred valve, per-AC — no new judgment layer.** When the acceptance-criteria rows covering a row's core path land in the deferred valve (outcome unreachable from the review environment, probe license exhausted), the documented-form comparison becomes **required substitute evidence** for that row. The Reviewer never issues an abstract "this row is unexecutable" ruling: the filed conflation objection — "I could not verify" vs "this cannot be verified" — is already drawn per-AC by the existing contract, where a failing probe is `not-met` (verifiable, failed) and unreachable is `deferred`. The two declaration channels remain first-class *raisers* of the same duty, earlier: an issue AC can ask for the comparison outright (it then rides the ordinary per-AC machinery), and a Worker can declare unexecutability in `judgmentCalls` mirrored into `reviewerFocusItems` (the focus sweep turns it into a directed check). Any one source triggers; none is a precondition; the deferred valve is the backstop that fires when nobody remembered.
- **The comparison's shape: a divergence list, never a verdict flip.** The Reviewer identifies the authoritative documented form for the unexecutable mechanism (vendor documentation, spec), compares the change as it stands on the branch, and reports **every** divergence, each classified `deliberate` (a commented departure) or not. Deliberate departures survive review intact; an uncommented divergence is ordinary Reviewer judgment like any other finding. The duty adds required *reporting*, not new *routing*.
- **Reporting: a flat optional `documentedFormComparison` field on the ReviewerVerdict** — `{ trigger: issue-declared | worker-declared | deferred-core-path, sources[], divergences[{ description, deliberate }] }`. Optional in the schema (flat, no conditional requirement — the no-top-level-`anyOf` lesson), required by contract prose whenever a trigger fired. `sources[]` is what makes the no-restatement constraint structural rather than hortatory: the operating contract's evidence-from-this-dispatch clause extends to documents — the comparison cites what the Reviewer itself read; a comparison whose only source is the Worker's report is invalid by construction. The G3 human brief renders the field mechanically.
- **Worker-side defense-in-depth, Reviewer-side anchor.** The Worker brief gains the clause: if your row's core path cannot be executed from the dev environment, declare it (`judgmentCalls`, mirrored `reviewerFocusItems`) and compare your own change against the documented form, reporting your divergences — the live-evidenced behavior worth keeping. The Reviewer's independent comparison remains the anchor; the division of labor is the established one (brief clause = defense-in-depth, structural duty = anchor).

## Considered Options

- **Issue-declares-only** (rejected) — honest, but relies on the foresight of exactly the author whose acceptance criteria missed the risk; the founding incident is the counterexample.
- **Worker-declares-only** (rejected) — closest to the evidence, and it worked live as behavior; but a forgotten or wrong report entry silently cancels the duty, and the misstatement-passthrough finding from the same wave sits in precisely this channel.
- **A new Reviewer-side unexecutability ruling** (rejected) — maximally memory-free, but re-creates the could-not/cannot conflation as a second, abstract judgment layer when the ADR-0004 Amendment's per-AC `deferred` state already draws the line operationally.
- **Tagged `reviewerFocusItems` entries instead of a schema field** (rejected) — zero schema change, per the ADR-0004-Amendment precedent; but the outcome would land as free text beside advisory noise, the sources requirement would stay prose, and the `riskClass` history is the standing evidence that a load-bearing routing/decision input wants a field its absence can be caught on.

## Consequences

- `REVIEWER_VERDICT_JSON_SCHEMA` in the workflow-driver template gains the optional field — the deliberately-unsplit consumer copy surface (ADR-0028), so the change is one template resync per consumer and conflicts with other driver-template issues at planning time; the schema-drift spec pins the new shape.
- The Reviewer agent contract and its checks reference gain the duty at the deferred valve; the Worker brief gains the declare-and-self-compare clause; the glossary gains **Documented-Form Comparison**.
- The founding incident stays testable: run against the release-workflow change as it stood at review time, the comparison must surface all three divergences — the implementation slice's worked example (#112).
- The duty is deliberately cheap to satisfy honestly: on a row with an executable core path, no trigger fires and the field is simply absent — the common case pays nothing.

## Amendment 2026-08-09 — a simulable consumer path is executable (doctrine-budget grill)

The valve's trigger reads "outcome unreachable from the review environment," and a live review showed a whole class where that reading is more conservative than the facts: a consumer-form path with no installed package to resolve against (this repo runs the source form on both distribution layers) **is reachable by simulating the consumer install** — `npm pack` of the branch's engine, install of the tarball into a throwaway repo outside the tree, then the shipped line verbatim. Executed live twice (wave `2026-08-01-release-text-currency`, row 398's Reviewer — exit 2, the documented refusal — and the #397 registry contrast that followed), both times converting would-be substitute evidence into real execution.

The declaration duty therefore gains a precondition: **before a core path is declared unexecutable, check whether the consumer form is simulable; a simulable path is executable, the simulation stands in for the consumer, and the deferred valve does not fire on it.** The check binds both declaration sites — the Worker before declaring in `judgmentCalls`, the Reviewer before accepting any trigger as final. Evidence trail: issue #407 (second finding).
