# Skill references resolve against the full-repo plugin clone — anchor discipline and dual-form invocations instead of inlining

Issue #202 filed an audit on the premise that an installed-plugin consumer receives skills whose repo pointers resolve to nothing — 10 ADR file links, 19 retro links, 36 engine-source references measured at filing, framed as the DA-F1/DA-F3 clean-room class extended to prose. Measured 2026-07-29 against the actual install surface (`~/.claude/plugins/cache/formtrieb/flotilla/<version>`, pinned SHA), the premise is false: `.claude-plugin/marketplace.json` declares `"source": "./"`, so the plugin ships the **entire repository** — `docs/adr/`, `docs/retros/`, `tools/wave/src/` are all present; only gitignored artifacts (`tools/wave/node_modules`) are absent. The defect class is real but relocated: a consumer session's cwd is the *consumer repo*, so what fails is resolution **anchoring**, not file **presence**. A hand-run prototype of the guard confirmed both halves: 88/88 bare path citations resolve against the clone root today, while 2 of 31 anchored links are dead — `convention-07-host-landing-seam.md` links `../wave-close/…`/`../wave-resume/…` one directory level short — and 3 more (`grill-with-docs/CONTEXT-FORMAT.md`) are illustrative examples that legitimately resolve to nothing. Real prey and a real allowlist case, on day one. Settled in a grill session 2026-07-29 (#202 refinement).

## Decision

- **Skill references may rely on the full-repo plugin clone.** The plugin's install surface *is* the repository at a pinned SHA; no referenced content is inlined (the ADR-0028 self-registering-reference pattern is not extended to ADRs/retros), nothing extra is shipped, and no citation is demoted. The npm package is a **different, narrower surface** (`src`, `bin` only — it ships no skills) and is out of this decision's scope.
- **Three reference classes, each judged against its own resolution anchor.** (a) **Anchored markdown links** (`../../../docs/adr/…`) resolve file-relative — the predicate is that the target exists relative to the *skill file*. (b) **Bare path citations** (`` `docs/retros/…` ``) are evidence identifiers read **clone-root-relative** — the predicate is that the target exists in the clone; they stay bare, because existence-pinning gives rename protection at zero edit cost. (c) **Command fragments** (`npx tsx tools/wave/src/cli.ts`) anchor on cwd *and* on installed artifacts the clone does not carry (`node_modules`) — every `{{wave-cli}}` resolution block therefore states the **dual form**, published-package form first (`npx @formtrieb/flotilla-engine`, the workflow-driver's settled default since #122), vendored in-repo form as the documented fallback. Narrative mentions of engine paths outside resolution blocks are class (b) identifiers, not invocations.
- **The reference-guard spec is the tripwire that keeps all three predicates true.** `tools/wave/src/skill-reference-guard.spec.ts` enumerates every shipped skill/agent markdown file (`.claude/skills/**`, `.claude/agents/*.md` — vendored skills included, they ship like any other), asserts the class predicates, and carries its allowlist as a named const with a one-line justification per entry, so every widening is visible in the diff that makes it. A permanent negative control runs a planted dead reference through the same extraction-and-resolution pipeline; Convention 11's one-time failing demonstration lands in the PR evidence.
- **Narrowing the package surface becomes a loud decision.** Any future move away from `"source": "./"` — shipping only `.claude/skills/`, say — turns the entire class-(a)/(b) population red in one run. That is deliberate: the guard converts a silent packaging regression into a failing gate that forces this ADR to be revisited explicitly.

## Considered Options

- **Inline the referenced content into the skills** (the filed issue's first menu entry, ADR-0028 pattern) — rejected: it solves a presence problem that does not exist, bloats every skill body, and creates a second copy-drift surface of exactly the kind the schema-drift spec exists to police.
- **Demote retro links to doc-slug identifiers** (the filed issue's second menu entry) — rejected: bare citations already *function* as identifiers, and the clone ships the files; demotion would spend ~24 edits to remove rename protection the existence predicate provides for free.
- **The filed missing-from-package predicate** — rejected on the strongest evidence available: it is trivially green today (the package contains everything), and it would have missed **both** live dead links, whose *targets exist* in the clone — the relative paths are wrong, not the files. Only the anchor-aware predicate catches the actual observed failure.
- **Excluding vendored skills (grill-with-docs) from the guard population** — rejected: they ship in the clone like every other skill, and a dead link there fails a consumer identically; the exception belongs on the allowlist per-reference with a reason, not structurally per-directory.

## Consequences

- #202's body is amended from "audit + decide per class" to "apply the settled classification + land the guard": the Gap restates the anchor defect class with the measured numbers, the per-class decisions above are recorded as settled input, and the ACs re-point at the two predicates plus the dual-form rule.
- The ~10–12 `{{wave-cli}}` resolution blocks gain the published-package form; the two `convention-07` links gain their missing directory level; the three CONTEXT-FORMAT example links seed the allowlist.
- The guard structurally pins the `"source": "./"` premise — the first spec in the suite whose subject is the *distribution surface* rather than engine behavior or schema copies.
- CONTEXT.md gains **Plugin clone**, **Resolution anchor**, and **Dual-form** under a new `### Distribution` section.

## Amendment (2026-07-29, post-implementation) — the landed guard corrected this ADR's measured numbers

The implementation slice (the wave that landed `skill-reference-guard.spec.ts`) proved three of the context paragraph's numbers wrong or narrower than the settled predicate — the *classification* stands unchanged; only the measurements and one operational addition are corrected here:

- **Class (b) was never 88/88 green.** The population count (88) was exact, but 2 of the 88 were dead **at the very SHA this ADR merged on**: `.claude/skills/README.md` cited `docs/superpowers/plans/2026-06-06-p7-overview.md` and `…-p7.1-integration-surface.md` — design docs the publication cut (ADR-0026) left in the private archive. The hand-run prototype behind the "88/88" line resolved against too coarse an existence check to catch them. The guard's Reviewer independently confirmed both dead at the anchor via `git show`. Both citations are now repointed (CHARTER + ADR-0009) rather than allowlisted — allowlisting a stale citation would have encoded a lie.
- **Class (a) is 77 links, not 31 — the anchored predicate carries no dot-prefix qualifier.** This ADR's worked examples were all `./`/`../`-prefixed and its prototype only counted those (31). The stated predicate — "the target exists relative to the skill file" — applies to every non-absolute, non-URL markdown link target, and the guard extracts all 77. That width is what surfaced a **third** dead link the prototype missed: `convention-05-sidecar-write-path.md` linking `reference/routing-mechanics.md` from inside `reference/` (unprefixed, one level too deep). The wider reading is the faithful one and is now the enforced one.
- **`RUNTIME_ARTIFACT_PREFIXES` operationalizes the gitignored carve-out.** The context paragraph named only `tools/wave/node_modules` as the clone's absence; the guard generalizes this into a named const (`.flotilla/`, `.claude/worktrees/`, `.claude/settings.local.json`, `.claude/projects/`, `tools/wave/node_modules/`, `tools/wave/coverage/`) that filters gitignored runtime paths out of the class-(b) population — asserting a runtime artifact exists in a clone would be a category error, so these are excluded structurally rather than allowlisted per occurrence.
