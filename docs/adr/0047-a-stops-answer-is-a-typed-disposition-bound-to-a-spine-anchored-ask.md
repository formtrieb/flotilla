# A STOP's answer is a typed disposition bound to a spine-anchored Ask, consumed through the engine

ADR-0006 serialized the *question* half of a STOP — kind, question, options — as the bridge to the headless-async topology (CHARTER §7, "design toward II; ship I"). The *answer* half was never specified: how a human's decision comes back machine-readably, and how a Coordinator that was not in the chat acts on it. The 2026-08-31 headless sketch ("the Coordinator as a pulse") named it the smallest brick with the largest lever, because the Companion App waits on the very same contract to write decisions back from a phone. Grilled 2026-09-01/02 against ADR-0002/0006/0018/0021/0022/0023/0024/0029. Three code findings shaped the answer: **(1)** ADR-0006's "the spine additionally records the pause" was never built — `resume()` derives `needs-attention` from sidecar/worktree evidence only, and nothing in the spine says which row waits on which question; **(2)** the state machine has **no human-decision event at all** — after the G3 STOP the interactive Coordinator continues by a direct `spine set-row-state <id> approved`, past `transition()`; **(3)** the flag's `options` are free strings composed in skill prose, so executing an answer today is an act of interpretation.

## Decision

1. **The option vocabulary is engine-owned, closed per STOP reason.** Every Ask offers the two terminal dispositions `park` and `abandon`, plus at most one reason-specific *continuation*: `approve` (`public-api-approval-required`), `answer` with a mandatory note (`reviewer-questions-blocking` — a Reviewer-only re-dispatch carrying the note, the 2026-08-16 ruling made mechanical), `retry` with an optional note (`re-dispatch-cap-exhausted`, `worker-failed`, `worker-stalled`), `reopen` (the resume-time `closed-unmerged` flag). `retry` also answers `dor-drift` — a row whose Definition of Ready failed since the cut: it is still `planned`, the Ask is raised without dispatching it, and `retry` means "re-check next run" (the row stays `planned`; a repeated failure raises a new Ask). `same-file-conflict` and a corrupt sidecar offer no continuation — a planning or artifact defect has none. Conflict-Map drift raises **no** Ask at all: overlap is a first-class wave shape, so the map is rewritten spine-first, disclosed wave-scoped, and the run continues (ADR-0048). The question prose stays the Coordinator's; `issue-store flag` takes `--reason` and derives the options. `escalate` (→ `ready-for-human`, ADR-0006's third terminal disposition) is deliberately **not** an option in v1: it is a triage act, not a wave act.
2. **An Ask has a spine-anchored identity.** Per row, a monotone number `<row>#a<n>`, written **spine-first** (an attention record: ask id, reason, kind, since) and only then carried to the tracker inside the flag payload. This is the WAL discipline of the dispatch-log (ADR-0021) applied to the pause, and it is what makes ADR-0006's unbuilt promise true: a paused row is knowable from the spine, and a later run can find its open Asks without reading state *into* the spine from the tracker (ADR-0002 holds — the tracker supplies the *answer*, never the *state*).
3. **The Answer lives as a structured comment, and its form is a published contract.** Sentinel `<!-- wave-answer v1 <ask-id> -->`, then the option, an optional note, and free prose; MarkdownFs realizes it as an `## Answer` block. Author and time come from the tracker. The facet is intent-shaped like the Triage facet: `answer(id, askId, option, note?)` and `readAnswer(id, askId)`; the adapter computes the native form; the conformance suite round-trips it on all three stores. Because the Companion App writes and reads this form **directly** through the tracker API, with no engine, the Ask comment and the Answer comment together become an **external contract governed by semver** — beside the package root, the config schema, and the CLI surface (ADR-0035). The version marker in the sentinel is the contract's handle.
4. **Authorization is read from the tracker, never re-modelled.** Default: GitHub `author_association ∈ {OWNER, MEMBER, COLLABORATOR}`; Linear **workspace member, not a guest**; MarkdownFs — whoever can edit the file. A configured allowlist *replaces* the default (it may narrow or widen). A rejected Answer — unauthorized author, an option outside the set, a stale ask id — is **reported, never applied, never silent** (the sweep's "owes accounting" posture, ADR-0042): on a public repo a stranger can trigger nothing, and the Operator still sees the attempt. The comment read in both API seams widens from `{ body }` to carry author, association and creation time.
5. **Continuations execute through `transition()`; dispositions stay Coordinator-set.** Four new `WaveEvent`s — `human-approve`, `human-answer`, `human-retry`, `human-reopen` — gain cells legal **only** from the state the STOP left the row in (`human-retry` from `planned` is the one self-transition: the `dor-drift` re-check); anywhere else they are `noop`, which by the `route-verdict` rule is a caller bug, never a legitimate nothing. `park` and `abandon` remain the scripted two-step ADR-0022 defined (`failed → parked`, claim released, flag cleared). A granted round (`retry`, `answer`) runs **outside** the cap=1 and is limited to **one per Ask** — the next exhaustion raises a new Ask — so termination stays guaranteed: every extra round costs a fresh human act. Consumption order is WAL: the spine records `answered` (option, author, time) → the run acts → `clearFlag`. The latest authorized Answer at consumption time wins (humans correct themselves); after consumption every further Answer to that Ask is stale.
6. **One path for both topologies.** The interactive Coordinator writes the Operator's chat decision through the same `answer` verb and consumes it through the same events — it is its own Scribe here, as it is for sidecars (ADR-0024). Nothing continues past a STOP by a direct state write any more, in either mode.

## Considered Options

- **Free option strings, the next run interprets** (rejected) — the vocabulary stays in prose and the execution in LLM judgment; a misread `approve` on a `public-API-change` row is exactly the silent failure structure exists to prevent (ADR-0034).
- **A label per option** (rejected) — one tap in an app, but no note, no ask identity, and a label vocabulary that grows per option; useless for `answer`.
- **A native state change as the answer** (rejected) — on Linear the state *is* the claim ledger (ADR-0020); writing a decision there confuses the question with the claim.
- **The tracker's comment id as the Ask identity** (rejected) — inverts the WAL (the flag would have to exist before the spine record) and is adapter-specific.
- **A derived identity `<id>-<iter>-<reason>`** (rejected) — collides on a repeated reason in one iteration.
- **A config-only allowlist** (rejected as the default) — a second ACL beside the tracker's own, which drifts; kept only as the explicit override.
- **Direct `set-row-state` on an Answer** (rejected) — the status quo of the interactive mode; it leaves legality in prose and would make the headless run the first place the hole is load-bearing.

## Consequences

- **Engine:** `NeedsAttentionPayload` gains `reason` and `askId`; the option set per reason is an exported const (the skill-schema-drift guard pins any inlined copy); the spine gains an attention block plus `spine open-ask` / `spine answer-ask` verbs; `transition()` gains the four events and their cells; `IssueStore` gains `answer` / `readAnswer`; `getComments` widens; conformance covers flag → answer → readAnswer → clearFlag on all three stores, including the rejection cases.
- **Skills:** `wave-start` step 8 flags with `--reason` and never composes options; its post-STOP continuation and `wave-resume`'s flags go through the Answer path; the report lists every rejected Answer.
- **Docs:** amends ADR-0006 (the pause record now exists, and the answer half is specified); leaves ADR-0022 untouched (park/abandon unchanged); CONTEXT gains **Ask** and **Answer**.
- **Semver:** the comment wire form is a public contract from its first release; the Companion App is its second consumer and reads the Ask comment to render options instead of the label alone.
- **Open, deliberately:** when a run *polls* for Answers is the pulse's business ([ADR-0048](0048-a-headless-coordinator-is-a-finite-pulse-on-a-leased-spine-branch.md)), not this protocol's.
