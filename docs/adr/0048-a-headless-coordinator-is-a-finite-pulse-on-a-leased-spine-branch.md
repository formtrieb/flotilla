# A headless Coordinator is a finite pulse on a leased spine branch

CHARTER §7 named two topologies — an interactive Coordinator (shipped) and a headless, tracker-async one (designed toward) — and §12 left the cross-coordinator compare-and-swap to M2. The 2026-08-31 sketch ("the Coordinator as a pulse") observed that the architecture is already event-sourced — the spine is a write-ahead log (ADR-0002), sidecars are durable events written at agent-return (ADR-0024), the tracker is the claim ledger, landing is arm-and-exit (ADR-0023) — so a live session does only two things a headless run cannot: drive the dispatch loop, and answer STOPs in chat. Grilled 2026-09-01/02 against ADR-0002/0006/0018/0021/0022/0023/0024/0029, with [ADR-0047](0047-a-stops-answer-is-a-typed-disposition-bound-to-a-spine-anchored-ask.md) settling the answer half first. Four sketch premises did not survive contact with the code and reshaped the design: the "wave branch" the spine supposedly rides **does not exist** (the spine sits on whatever branch the Coordinator's checkout is on, and flotilla's own repo gitignores `.flotilla/` wholesale); the **double-dispatch guard is machine-local** (`resume()` joins the spine against `git worktree list`), so it cannot protect two runners; a push at the *end* of a run is a CAS that fires after the damage; and "STOPs park the row" collided with the glossary's `parked` (terminal, claim-releasing) — a stopped row is *paused*, and the pattern is **flag-and-continue**.

## Decision

1. **The Pulse.** A finite, triggered, unattended Coordinator run: select a wave → take the Lease → reconcile → consume Answers → advance everything advanceable, round after round, until **Quiescence** (every row `in-review`, paused on an open Ask, HELD/HUMAN-HELD, or terminal) → arm what the wave's own landing authorization allows → write the end entry → exit with an operator report. Between pulses there is no process, only state. It is one station, `wave-pulse`, that *invokes* the existing ones in this fixed order — the `wave-resume` reconcile core, `wave-start` in flag-and-continue mode, `wave-close --auto` under per-wave pre-authorization — and duplicates none of their mechanics; the order (reconcile before dispatch, answers before dispatch, arm after routing, publish last) is doctrine, and doctrine gets one home. A `--headless` flag on each station, chained by a runner script, was rejected: it would re-derive that order per runner.
2. **The spine has its own branch, `spine/<slug>`.** Born at `wave-create` from the wave anchor, pushed before the first claim, carrying nothing but the spine and its sidecars. Deliberately outside the `wave/*` namespace of the row branches, which `wave-close` sweeps after landing. It lands on `main` **exactly once — archived**, as the Coordinator-direct PR ADR-0033 reserves for orchestration artifacts (the merge-base is the anchor, so the diff is `.flotilla/` alone); `wave-close`'s `git mv` + local commit becomes that PR. flotilla's own repo un-ignores `.flotilla/waves/` (the config file stays ignored — it is client-identifying) so it can be the first consumer of this seam, as of every seam before it. `wave-setup` probes the remote for pre-existing `spine/*` refs and reports, never dictates.
3. **Durable means on the remote — publish per write, inside the verbs.** The runner's disk is ephemeral, so "the spine is committed for resume" is not enough: a run that dies after hours of Worker time would take every locally-written sidecar with it, re-opening ADR-0024's P-1 window at repo scale. The sidecar write verbs and the spine verbs gain `--publish` (add + commit + push, an engine-owned `git` spawn with a bounded retry on `index.lock`); Scribes and the Coordinator call the same verbs they call today, with one flag more. No new Bash grant reaches any agent: the git write happens *inside* the allowlisted CLI invocation, the ADR-0029 figure. The WAL doctrine extends as the sketch asked — **spine-push first, then label.** The same discipline holds interactively; one rule, not two. This is the first time the engine pushes; it already spawns `git` for diffs, merge-trees, and the worktree sweep.
4. **The Lease is the Pulse-Log start entry, pushed before anything is dispatched — that push is the compare-and-swap.** A non-fast-forward rejection means another run holds `spine/<slug>`: exit ≠ 0, nothing touched, no Ask. Every later push by the holder is conflict-free by construction; a rejection mid-run means the lease was taken by force, and the run aborts and reports. The end entry releases. **A run cannot outlive its lease:** the maximum pulse lifetime is one config value, and the runner's own timeout (CI `timeout-minutes`, or the station's own deadline on a laptop) is the *same* value — so a start entry older than that with no end entry belongs to a provably dead run, and the next run takes over, recording `takeover-of`. No heartbeat. Interactive dispatching passes take and release the lease exactly the same way: two Operators on one wave are serialized structurally. This is the M2 cross-coordinator CAS CHARTER §12 deferred, obtained from git.
5. **Adopt is adopt-by-branch.** `resume` gains a fourth input — the remote heads (`git ls-remote --heads origin`, a read-only spawn gathered by the CLI subverb; the pure `resume()` stays I/O-free) — and decides on a foreign machine: published report → `adopt` (the Reviewer already fetches the branch into its own worktree); no report but the remote branch exists → `adopt`, a fresh worktree from `origin/<branch>`, the Worker re-run there without consuming the cap (the cross-machine form of "re-run into the same tree"); neither → `redispatch`. `resume` never deletes a remote branch; the crash-clean sweeps local debris only. Stated consequence: **a Worker's unpushed commits do not exist** for the next run — not a new hardship, the honest form of what ephemeral runners impose, and the Worker brief already pushes at every step.
6. **STOP handling in a pulse is flag-and-continue.** A row STOP raises its Ask (ADR-0047) and the run moves on; the row is *paused* — fine state preserved, claim kept — never `parked`. Answers are read at reconcile and once more at quiescence before exit, never continuously. Two "drift" STOPs degrade rather than halt: **Conflict-Map drift** is recomputed, written spine-first, disclosed wave-scoped, and the run continues — overlap is a first-class wave shape whose only cost is a longer landing tail, which partial-arm already leaves to the human; **DOR drift** becomes a row Ask (`dor-drift`: `retry · park · abandon`) on the still-`planned` row while the rest dispatches. Intra-wave lanes advance *within* a pulse: after each routing round the HELD rows are re-checked and the released ones dispatched, until quiescence. What remains a **wave-level STOP** is only the precondition class — another wave in flight, a red credential probe, an absent engine binding, a spine not `ready`: exit ≠ 0, the reason in the Pulse-Log, the runner's own failure surface as the human's signal.
7. **The wave queue: humans plan, the pulse sequences.** A pulse never plans and never creates; it selects its wave — the one with live rows if any, else the oldest `ready` spine on the remote's `spine/*` branches — so an Operator plans and cuts several waves in one sitting and the day runs unattended, one wave in flight at a time (the existing wave-level guard). Staleness across waves is caught by the entry gates that already exist: a later wave whose premises moved after an earlier one landed hits DOR drift (a row Ask) or Conflict-Map drift (recorded, continued), never a silent misdispatch.
8. **Landing authorization is per wave, given at the cut.** `wave-close --auto`'s headless bypass (`--pre-authorized`, ADR-0023) is not a standing config value — that would turn one confirm per wave into one decision per repo, forever. It is a spine frontmatter fact written at `wave-create` by the human who cuts the wave, through a verb, never by hand; a wave without it keeps its approved rows `in-review` for a human `wave-close`. The G3 row Ask stands regardless: a `public-API-change` row never arms without a human `approve`.
9. **Two nevers.** The pulse **never archives** — the disclosure gate needs human dispositions (ADR-0027), and the archive PR is the spine branch's one landing. The pulse **never plans** — `wave-plan`/`wave-create` stay interactive; no automaton enlarges a wave (the goal doctrine's "sight, never permission", ADR-0044, held headless). Headless moves *where* a decision is made, never *whether*.

## Considered Options

- **A daemon / watcher** (rejected) — the reconcile philosophy is "heal on next touch" with an evidence hierarchy; that *is* polling semantics. A cron pulse is the native form; webhooks are v2 comfort.
- **CAS at the end of the run** (rejected — the sketch's literal shape) — protects after both runs have dispatched; the worktree guard is machine-local, so the race it was meant to lose is exactly the double dispatch it would not prevent.
- **Heartbeat commits for lease liveness** (rejected) — more machinery and pushes, and a takeover threshold is still needed; binding the lease's expiry to the runner's own timeout gives the same guarantee from one value.
- **A human clears every stale lease** (rejected) — on ephemeral runners a dead run is the normal failure, not the exception; needing a person for each one abolishes headless.
- **CI `concurrency:` groups as the only overlap guard** (rejected as sole) — covers CI-vs-CI, not laptop-vs-CI.
- **Push only at pulse end** (rejected) — loses every locally-written sidecar with the runner's disk.
- **Scribes push through their own Bash** (rejected) — a new `git push origin spine/:*` grant for every agent, and parallel Scribes racing on one checkout's `index.lock`; the verb owns the push instead.
- **The spine stays on the Coordinator's current branch** (rejected — the status quo) — works only while the same machine pulses.
- **A wave-scoped Ask for wave-level STOPs** (rejected) — every candidate surface (the Goal container, the PRD, a "wave issue") invents a new one; a broken precondition is not a decision, it is a fix.
- **The pulse plans the next wave itself** (rejected) — moves the *whether*. **The next wave's recommendation as an Ask the Operator answers from a phone** is the named v2 step, pending a wave-less Ask surface.
- **A standing `preAuthorizedArm` config** (rejected) — see decision 8.

## Consequences

- **Engine:** `spine` gains a Pulse-Log section and verbs (`pulse-start` with the lease semantics, `pulse-end`), a landing-authorization frontmatter verb, and `--publish` on the spine and sidecar write verbs (git spawn, bounded `index.lock` retry, typed rejection error); `resume` gains remote-head input and the adopt-by-branch cells; `wave-config` gains `pulse.maxLifetime`; `cross-wave`/spine gain a Conflict-Map rewrite verb for the drift degrade. Nothing in the engine calls a harness primitive (ADR-0018 holds).
- **Skills:** new `wave-pulse` station (Operator-register report at exit, Convention 16); `wave-create` creates and pushes `spine/<slug>` and records the landing authorization; `wave-start` gains flag-and-continue, the drift degrades, the in-pulse lane loop, and takes the lease; `wave-close` phase 6 becomes the archive PR from the spine branch; `wave-resume` reads remote heads; `wave-setup` probes `spine/*` and scaffolds the runner example (a GitHub Actions workflow with `timeout-minutes` = `pulse.maxLifetime`, `concurrency` per spine, and the `-p` prompt carrying the explicit workflow opt-in words — `ultracode` is ignored in `-p` mode).
- **Docs:** CONTEXT gains **Pulse**, **Quiescence**, **Pulse-Log**, **Lease**, and the Spine entry's branch; CHARTER §7's "design toward II" and §12's CAS deferral point here; amends ADR-0002 (the guard becomes branch-aware and cross-machine; the WAL order gains the push), ADR-0021 (the durable branch home is now also the durable *remote*), ADR-0024 (the Scribe's write publishes), ADR-0023 (pre-authorization is per wave, in the spine), ADR-0008 (the spine is still local markdown — now on a branch of its own).
- **Spikes before the build, not after:** (a) `claude -p` waits for background workflows, capped at a continuous-idle ceiling (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`, 10 min default) — whether an hours-long Worker phase counts as idle is unverified and decides the v1 runner shape; (b) the tracked `permissions.allow` parity in `-p` mode is documented as the same evaluation but not explicitly confirmed — the first live pulse proves it; (c) the `-p` prompt's workflow opt-in wording.
- **v1 boundary, stated:** the pulse lives while its Workers run — no Worker survives a pulse, no detached harvest. Roaming pulses as the normal case, webhook triggers, the proposal-as-Ask, the stale-claim reaper, and the rebase-train at the arm step (ordered landing of the Conflict-Map tail) are v2.
